**Goal:** Make the clip book obvious: one global book, newest first, a single filter row, a detail card with Copy, Send to…, and Delete, and the same book as a section on every machine page. Then make a file transfer survive leaving the page, and tell that person through an account toast.

## Decisions

- Filter row, one line, no wrap. If it does not fit, the buttons scroll inside the row. Search sits on that same row.
- Three places: All | Text / Picture / File / Folder | Missing / Offline / Available.
- All clears the kind and the status. The kind and the status can both be on. Search narrows both.
- The first press on a kind or status selects its first word. The next press cycles. The button shows the active word, or the first word when that side is clear.
- Stats stay in the book. They show under All and under a status filter. They do not have a kind button.
- Newest first. Equal timestamps keep the later add first.
- A row shows a type icon, the word, the name, the source machine, a preview, the time, and Missing or Offline when that is the state. Available has no extra mark.
- The detail card says the kind, the machine, the time, and the content. Missing says the content is gone. Offline says that machine is not answering.
- Actions are Copy, Send to…, and Delete. On a machine section the send action is Send to this machine, and only when that machine can take the clip.
- This server can take text on its desktop clipboard and can take a file, picture, or folder into a folder. The folder starts at Home.
- A joined computer or a virtual machine can take a file or picture into a folder only when its connector is online and files are allowed. A virtual machine without a connector still shows the book and does not offer Send to this machine.
- Text send to another computer’s own clipboard is not available yet. Copy still puts that text on this device. The card says so. Do not pretend the remote clipboard was set.
- A folder can be saved on this server. Sending a whole folder to another computer is refused with a clear sentence.
- Several selected files are one clip. Cut does not remove the source until the paste has finished. On this server a cut moves the file. On another computer the bytes are written first, then the source is removed.
- Ordinary Copy in Files (the Copy action, a multi-selection Copy, and Ctrl+C / Ctrl+X) fills the book. The separate Clip book menu item goes away. Ctrl+X records a cut and does not delete yet.
- Terminal Ctrl+Shift+C fills the book, as the right-click copy already does.
- The old capture forms (stats dropdowns, “browse a computer”) leave the global page. On a machine that can be read, one row, Clip the readings, stores that machine’s snapshot.
- Several clips can be checked and sent together. Text and stats join onto one clipboard, in the order given, with a blank line between them. Files, pictures, and folders go into one chosen folder, one paste at a time, and a failure does not stop the rest. A mix of text and files is refused: “Text and files go to different places.” Missing blocks the batch. A folder batch is blocked when one source is offline, or when the only place that could take it cannot take a whole folder.
- Each row has a checkbox, Send, and Delete. Delete asks in a small confirm next to the row. Send that needs a folder opens a short sheet. The detail card still has Copy, Send, and Delete. The selection bar stays on screen while clips are checked. Tasks 1–8 send files in the open page. Task 14 replaces that loop with a transfer saved for the account. The page no longer has to stay open.

## Transfers, toasts, and where Clip book sits

Tasks 1–8 are the book. This section is the rest of the agreed work. `deliverFiles` starts a server transfer. The global Clip book lists it. A machine section does not.

### What is already true

- A bulk send is an account transfer on this server. It keeps going after the page closes. The global Clip book shows progress, Resume, Cancel, and Dismiss.
- One file sent to another computer is all-or-nothing. The connector writes a temporary file and puts it in place only when the whole file has arrived. A drop leaves no half file. The next attempt sends the whole file again.
- A folder copied on this server can stop in the middle and leave part of the tree.
- Text and stats already join in one `clips.paste` when `ids` has more than one id and the destination is `{clipboard: 'server'}`.
- The bell (`notifications.get`) is one list for the whole server. Anyone signed in sees it. Today it is mainly “a new version is available.”
- A toast is React state in this browser. A success stays 2.6 seconds, an error 4.5 seconds, and the next toast replaces it. It is not saved.
- The floating character (`AssistantCharacterWidget`) is on unless the account turns Floating character off. On a phone its z-index is 30, so a sheet (z-index 52) covers it. On the desktop the character is z-index 99990.
- Clip book opens from the System row, on the phone (`#/clips`) and as a desktop window (`kind: 'clips'`). It is already in `SYS` (title, clipboard icon, size). It is not in `SYSTEM_DOCK`, not in the Activities `webKeys` list, and not in Personalize `allKeys`. The phone dock stays Home, Apps, Files, Machines, System. The top bar is status and the bell.

### Decisions

- A transfer is a record for that account, on disk, and the server keeps running it after the page closes and after a restart. The global Clip book shows it. A machine section of the same component does not.
- The unit of resume is a clip. Clips that already landed are not sent again. A file that failed is sent again from the start. Mark a clip landed only after `clips.paste` returns. Store the destination path it returned. On resume, if that path is already there with the same size, skip it, so a lost reply does not copy the file twice.
- A short drop (the machine stops answering, the connection breaks) is tried three times on that clip, then the transfer pauses. Resume continues from that clip. Clips that are gone, or whose file changed, stay failed and are not tried again. The rest of the transfer still runs.
- One transfer runs at a time for the account. Another waits in a queue. Clips already in a waiting or running transfer are not added again.
- Progress is how many clips have landed, out of how many, and the name of the one moving now. There is no byte bar inside one file.
- Cancel stops after the current file finishes or fails. Files that landed stay. Resume is not offered for a cancelled transfer.
- A finished transfer and a cancelled one stay on the global Clip book until dismissed. A paused one stays until Resume succeeds or it is dismissed.
- Text and stats stay one clipboard write. They are not a transfer.
- The bell stays for an outside event the whole server shares. A transfer does not go on the bell.
- An account toast is one record for that person: the words, when it was created, where a click opens, a level (`note` or `problem`), and a lifespan. A lifespan is an absolute expiry time, or until dismiss. Dismiss is the X, or the click that opens the feature. Either one clears it on every browser signed in to that account. The file survives a server restart. A timed toast whose time has passed stays hidden, including across a restart.
- Button feedback with nowhere to open and a few seconds of life (“Copied”, “Deleted”) stays in this browser. It is not written to the account, so another device does not flash it.
- Account toasts stack. Problems come first, then newer notes. A short local toast can sit with them and leave without clearing them.
- The assistant speaks the account toast that matters most: a problem ahead of a note. The bubble is that same record. It uses the character the person chose. It does not open the assistant chat and it is not written into the chat. When the character is hidden, turned off, or covered by a sheet, the same toasts sit in the box at the top. Do not show the bubble and the box at once.
- A transfer writes three toasts. Started and finished are notes, they open the global Clip book, and they expire after about eight seconds. A problem stays until dismiss and also opens the global Clip book. One problem covers a pause or a finish that still has failed clips. A clean finish is the finished note, not a problem.
- Clip book can be pinned to the desktop dock and placed as a desktop icon, the same way Assistant and Appearance can. Add it to Activities and to the Personalize lists. Leave it off the default dock. Do not add it to the phone dock, the top bar, or as pin buttons on the Clip book page. Right-click Pin to dock and Add to desktop apply once the key is in those lists. `info('clips')` already resolves through `SYS`.

### Ideas kept, and ideas set aside

- The server owns the transfer so two phones cannot copy the same files at once. The queue is the way a second send waits.
- A folder copied on this server can leave a partial tree if the process dies mid-copy. Resume uses the saved destination path and size. It does not invent a second copy when that path is already complete.
- The character is the messenger. The Clip book is the record. The toast file is the account’s list of messages. None of the three replaces the others.
- Set aside: a byte-by-byte bar, sending a whole folder to another computer, sending every path inside one multi-path clip to another computer (only the first path is sent today), writing text onto another computer’s clipboard, lengthening the 2.6 second “Copied” toast, pin controls on the Clip book page.
